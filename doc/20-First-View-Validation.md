# First-view validation — 7.12.0

User-authorized minor release, based on 7.11.16. The Assets panel filters all first-view candidates or one creative size and shows candidate totals per size. Paths remain package-relative to distinguish duplicate basenames.

The static model selects the first numerically named tab for each supported artboard, persistent artboard artwork, and every state within that tab, including hidden/hover/mousedown/active imagery. Custom references, linked Smart Objects and exact-then-retina raster resolution use the asset contract. Each resolved path counts once per size. All package CSS/JS/fonts and recognized teaser/peel logos are conservatively shared. Video is excluded. Turbo-generated videoN.jpg/jpeg and teaserVideo.jpg/jpeg posters are excluded per user instruction.

Limits use binary units consistent with the existing UI: first view strictly below 512000 bytes, teaser logos at most 10240 bytes, primary video (v1 playlist reference or video1.mp4) at most 2621440 bytes. Logo and primary video oversize conditions appear in Findings. Duration over 30 seconds is supported through long-form handling; no duration failure is generated.

These are candidate estimates, not network measurements or compliance certificates. Framework dependencies cannot be reliably identified from filenames, so shared scripts remain candidates pending review. Unresolved generated dependencies, feeds, disclaimer images, Master-derived imagery and secondary-container preload behavior may require additional served-request inspection. Below-limit totals never claim pass. No product is assumed to preload a main unit on initial impression: confirm click versus peekaboo loading in production. Video metadata/encoding and long-form behavior are not established by archive size alone.

Manual production review covers priority containers (prior guideline unavailable), background images, secondary child containers, no automatic end-of-video tab/playlist changes, click-to-continue engagement rules, offload pixel, fragmentation and CPU. The internal encoding page was inaccessible; no encoding values were invented. Struck-through mobile teaser/blank-composition rules are not enforced. Heavy-font text-images are an optional static-creative authoring choice and do not change live text rendering.

Validation: 138 project-suite checks and 24 QA-engine checks passed, with real archive analysis on Ipsen, Cosentyx HCP and SPIRIVA. TypeScript passed. Production bundling could not complete: the default Node is 20.11; an available Node 24 runtime exposed an unusable Rolldown native binding. No dependency installation or lockfile reset was performed.

## User correction — simple filter and errors

The explanatory validation panel is removed. First view filters the inventory by first-tab assets including primary video (v1 or video1.mp4) and autogenerated posters. Video and autogenerated posters remain excluded from the combined 500 KB calculation; generated posters remain exempt from validation. Size violations are errors in Findings and in each affected asset row. Combined-budget errors on contributing rows explicitly describe the combined per-size total, not an individual-file limit. The release remains 7.12.0 as a continuation of the authorized feature.

## Video severity and table order correction

Primary video size over 2.5 MB or duration over 30 seconds is a warning. Duration strictly over 4:30 (270 seconds) is an error. Browser metadata supplies duration; unavailable metadata is a warning rather than an assumed pass. Non-video errors are unchanged. Table order: Asset, Type, Size, Validation, Status, References.
