# LaRoche 970×546 tab 1 — production and preview comparison

Compared September 14, 2026 against the user-confirmed
`preview/turbo-preview-7.8.0.html`, supplied `design_1.psb.zip`, and supplied
production HTML fragment. The extracted export was checked for equality with
the ZIP's `export.json`.

Preview structure was generated by executing its actual parser and
`paintArtboard(entry, 'tab1', null)` at scale 1 with a minimal DOM implementation.
This establishes emitted ancestry, inline geometry and markup. It does not
establish computed CSS, glyph geometry, browser screenshots or player behavior.
Post-font text synchronization callbacks were not executed. Production values
below are supplied inline CSS, not measurements from a running production page.

## Result

Source ancestry is preserved, but production container geometry and component
conversion are not yet reproduced. All 21 distinct source layer IDs exposed in
the selected production content are present in preview, with matching nearest
source-layer parents. Production-generated wrappers have additional ancestry.
The production CTA text wrapper has no numeric layer tag; its correspondence
to source text 222520 is established through the button parent and label.

## Why the artwork can still look correctly placed

Large preview child offsets compensate for incorrect group origins.
For example, DERMTOLOGIST-TESTED is locally at 0,1 in production's ICONS group
but 2603,477 in preview's group. Both resolve to artboard position 22,452.
All five icon images and both product images have matching emitted artboard
positions and dimensions. Matching artwork placement does not prove correct
container layout.

The supplied full production hierarchy resolves the CTA to artboard position
712.344,481.844. Preview resolves it to 712.34375,481.84375; the difference is
rounding. The earlier isolated CTA fragment's 693.344,380.844 values were
CanvasDesign-relative coordinates, not artboard-relative coordinates. The
full fragment now establishes that relationship.

CTA label local position also matches: production 25.6562,14.1562;
preview 25.65625,14.15625. The frame's disabled stroke remains disabled in both
supplied states.

## Conversion and runtime differences

- Production promotes tab1's black background into its container; preview
  paints frame layer 9 separately. Preview also paints root frame 7 and header
  frame 104 separately, instead of consuming them for component/container
  geometry and drawing roles.
- Production uses a logo container with background sizing of `501px auto`;
  preview retains background image layer 31082 as an image child with
  `object-fit: contain`.
- Production inserts tabs component, collection and active tabpanel wrappers
  between tabComponent and tab1. Preview directly nests its source groups and
  repaints the selected state. It does not reproduce that runtime tree.
- Production video layer 18 is a wrapper at 0,81 with width 640, automatic
  height and aspect ratio 1.77654. Preview emits a direct video element with
  dimensions 640 × 361. The nominal artboard rectangle agrees to rounding;
  player controls and lifecycle are not equivalent structures.
- TabButtons has matching outer inline geometry: 657,50,298 × 28. This alone
  does not certify internal menu/player behavior.
- Ordinary preview containers use visible overflow and no inferred group
  effects. The pasted inline HTML cannot establish all clipping, masks,
  transforms, opacity or stacking rules supplied by production stylesheets.

## Text limits

Production's headline wrapper is 278.148px wide and its paragraph has offsets
−3px,1px. Preview initially emits a 274px wrapper. Production CTA label width
is 135.273px; preview initially emits 133px. Preview has post-font PSD text
synchronization, which was not exercised here. These are initial-markup
differences, not confirmed final glyph mismatches.

## Evidence-based implementation direction

Use the established content bounds for ordinary groups and explicit owning
frames for frame-derived components; rebase children into those containers.
Track consumed frame/background IDs so they are not independently painted.
Handle tab/player conversion separately from ordinary source ancestry.
Validate post-font text in a browser before asserting visual parity.
This comparison changes neither renderer behavior nor validation rules.
